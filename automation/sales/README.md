# BASE AI Sales Engine

目的はSNS投稿数を増やすことではなく、株式会社BASEの新規相談と売上につながる見込み客導線を作ることです。

## 基本フロー

1. 売る入口商品を固定する
2. 見込み客が抱える具体的な困りごとをテーマ化する
3. SNS短尺動画・投稿文を自動生成する
4. 投稿本文でLINE相談へ誘導する
5. 問い合わせ内容を「課題 / 現状 / 希望 / 緊急度 / 予算感」に整理する
6. 提案骨子と見積り確認事項をAIが下書きする
7. 人が確認して提案・契約へ進める
8. 反応の良いテーマを次の投稿企画へ戻す

## 入口商品

`offer_catalog.json` の「業務自動化ミニパック 33,000円〜」を第一入口とする。

SNSでは価格だけを強く押し出さず、「毎日の繰り返し作業を1つ減らす」という課題解決を先に見せる。CTAはLINE相談へ統一する。

## 投稿の役割

- 認知投稿: 困りごとに気づいてもらう
- 教育投稿: 小さく自動化できることを知ってもらう
- 実例型投稿: どんな作業が対象になるか具体例を見せる
- 商品投稿: ミニパックの入口を説明する
- CTA投稿: 「自動化相談」とLINEで送ってもらう

5本を1サイクルとして回し、売り込みだけのアカウントにしない。

## 現在実装済み

- `offer_catalog.json`: 入口商品の価格・対象・CTA・安全条件を機械可読化
- `intake_schema.json`: 初回相談で取得する項目・営業ステータスを定義
- `../sns/enrich_sales_cta.py`: 生成済みSNS投稿にLINE相談導線を自動追加
- `lead_qualifier.py`: 問い合わせ文章をA/B/C優先度に整理し、確認質問を下書き
- `proposal_builder.py`: 整理済み相談から提案骨子・見積り前確認事項・返信文案を生成
- `../sns/buffer_approve_queue.py`: 人が承認した3媒体の下書きだけをBuffer Queueへ移すゲート
- `.github/workflows/sns-daily-preview.yml`: 月・水・金の承認待ち動画に営業CTAを組み込む準備
- 顧客相談の実データは `automation/sales/output/` に保存し、Git管理対象外にする

## 非公開の実運用領域

Google Driveに以下を準備済み。

- `BASE AI営業｜見込み客・相談管理`: 相談、優先度、次アクション、見積状況、成約状況、KPIを管理
- `BASE｜業務自動化ミニパック 提案書テンプレート`: 人が確認して顧客向け提案書へ仕上げるためのテンプレート

実顧客の相談本文・個人情報は公開GitHubへ保存しない。

## 次の接続先

LINEで届いた相談を自動取得する部分はまだ接続していない。受信経路を接続できたら、

`LINE受信 → 非公開保存 → lead_qualifier.py → proposal_builder.py → 人の承認 → 返信・見積り`

の順でつなぐ。

## 安全ゲート

- SNS本投稿は承認されたものだけ
- 個別企業への営業メール・DM・返信は人の承認なしに送信しない
- 契約・値引き・支出は自動実行しない
- 削減時間・売上増など未検証数値を断定しない
- 顧客相談の本文や個人情報はGitHubへコミットしない
- `33,000円〜` は入口価格であり、内容確認前に確定価格として提示しない
